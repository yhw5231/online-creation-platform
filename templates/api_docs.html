API 接口文档
OpenAI 兼容的 /v1/images/generations 接口，积分扣减规则与网页完全相同
1. 获取 API Key

登录后进入 个人主页 →「API Key」卡片：

  • 可生成多个 API Key，每个 Key 需填写名称（如「官网小程序」「脚本A」）用于区分用途
  • 每个 Key 在生成时必须绑定一个生成渠道：/v1/images/generations 的 OpenAI 格式请求中没有渠道参数，因此「用哪个渠道」在创建 Key 时就固定下来，无法在调用时更改
  • 新 Key 明文仅显示一次，请立即复制保存；数据库只存 SHA-256 哈希，无法找回明文
  • 随时可删除任意 Key（删除后该 Key 立即失效），也可继续生成更多 Key
2. 认证方式

所有接口请求头携带任意一个有效 Key 即可（二选一）：

Authorization: Bearer sk-xxxxxxxx
X-API-Key: sk-xxxxxxxx

Key 缺失 / 无效 / 账号被禁用均返回 HTTP 401。

3. 生成图片

POST /v1/images/generations（OpenAI Images API 兼容格式，JSON 请求体）

参数必填说明
prompt是提示词，最长 4000 字
model否生成模型，须为该 Key 绑定渠道支持的模型；留空自动用渠道默认模型
n否生成数量，1–4，默认 1
size否OpenAI 尺寸，如 1024x1024 / 1792x1024 / 1024x1792，自动换算为宽高比与分辨率档位；默认 1024x1024
response_format否url（默认，返回图片地址）/ b64_json（返回图片 base64 内容）

「渠道」等本站专有参数已随 API Key 绑定，请求体中无需也不能指定。

同步返回：本接口会等待图片生成完成后一次性返回结果（OpenAI 语义）。成功响应：

{
  "created": 1750000000,
  "data": [
    {"url": "/images/1750000000000_ab12cd.png"}
  ]
}

请求 response_format=b64_json 时 data 每项为 {"b64_json": "..."}。图片地址拼接站点地址即可下载：http://127.0.0.1:8900/images/1750000000000_ab12cd.png

4. 查询任务状态（旧接口）

GET /api/v1/status?task_id=xxx（仅用于兼容旧版调用方，新代码无需使用）

成功响应：

{
  "ok": true,
  "task_id": 123,
  "status": "success",
  "prompt": "一只猫",
  "images": ["/images/xxx.png"],
  "error": "",
  "created_at": "2026-08-16T12:00:00+08:00"
}
  • status：processing（生成中，建议每 2–3 秒轮询）/ success（成功，images 为图片路径列表）/ failed（失败，error 为原因，积分已退回）
  • task_id 不存在或不属于该 Key 的账户：返回 404
5. 查询可用渠道

GET /api/v1/channels（需要 API Key，返回当前配置的全部生成渠道与各自的稳定编号）

{
  "ok": true,
  "channels": [
    {
      "id": 1,
      "index": 0,
      "name": "主渠道",
      "nsfw": false,
      "model": "grok-imagine-image-lite",
      "resolutions": ["1k", "2k"],
      "models": ["grok-imagine-image-lite", "grok-imagine-image"]
    },
    {
      "id": 3,
      "index": 1,
      "name": "NSFW 渠道",
      "nsfw": true,
      "model": "grok-imagine-video",
      "resolutions": ["1k", "2k", "4k"],
      "models": ["grok-imagine-video"]
    }
  ],
  "hint": "channel 参数填写渠道编号（id 字段，字符串，从 1 开始）；编号为渠道创建时分配，不随增删/排序变化。留空自动选第一个普通渠道"
}
  • id 即个人主页生成 API Key 时「绑定渠道」下拉的取值
  • name 与创作页面「生成渠道」下拉中的渠道名一致（NSFW 渠道在页面显示为「（NSFW）」）
  • resolutions / models 为该渠道支持的档位与模型，便于创建 Key 前确认
  • index 仅为当前列表的展示顺序，会随渠道增删变化，请勿用作渠道标识
6. curl 完整示例
# 生成图片（OpenAI 兼容，同步返回）
curl -X POST http://127.0.0.1:8900/v1/images/generations \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"一只猫","n":1,"size":"1024x1024"}'

# 生成 2 张并返回 base64
curl -X POST http://127.0.0.1:8900/v1/images/generations \
  -H "Authorization: Bearer sk-xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"一只猫","n":2,"response_format":"b64_json"}'

# 查询可用渠道（创建 API Key 前确认渠道编号）
curl "http://127.0.0.1:8900/api/v1/channels" -H "Authorization: Bearer sk-xxxxxxxx"

# 下载图片（无需 Key）
curl -o cat.png "http://127.0.0.1:8900/images/xxx.png"

更多 Python 调用示例见项目 docs/api.md。

7. 错误码
HTTP说明
400参数错误：无效 JSON / prompt 为空或超长 / size 或模型不被渠道支持 / response_format 非法，error.message 为具体原因
401API Key 缺失或无效
402积分不足（error.message 含所需积分，此次不扣分）
405使用了错误的 HTTP 方法
500系统繁忙 / 任务创建失败（此情况积分已退回）
